# 美化小叽 · 项目约定（v0.9.1+）

## 版本与更新日志规则（强制）
**每次返修 / 更新 / 新增功能 / 修复 bug 后，必须自动执行以下操作，无需询问用户：**
1. 升 `APP_VERSION`（按语义版本：修复 bug 升 patch 如 0.9.1→0.9.2，新功能升 minor 如 0.9→0.10，大改升 major）
2. CHANGELOG 顶部新增对应版本条目（含日期 + 改动项，标签用 add/chg/fix）
3. 同步所有版本显示位：顶栏 `brandVer`、首页 chip、更新日志徽标 `clBadge`
4. GetDiagnostics 验证 0 错误

## UI 风格基准（v0.9.1 确立）
- **核心风格**：Neumorphism 拟态，不是纯玻璃
- **玻璃仅限**：弹窗 / 启动画面 / 语音条 / 表情半窗
- **拟态参数**：阴影 6px/12px，圆角 26px（卡片）/ 16px（按钮），曲线 `cubic-bezier(0.34,1.56,0.64,1)`
- **文字色**：全部走 `--text-primary` / `--text-secondary` / `--text-disabled`，禁止硬编码
- **表面色**：`--surface` / `--surface-2` / `--surface-3`
- **反色白字**：`--ink-inv`（深色按钮/气泡上）
- **图标**：纯 SVG 线条，不用 emoji；Dock 4 按钮（主页/功能/设置/小淮宝），小淮宝用机器人头图标

## 部署规则
1. 用户说"上线"时，自动执行：git add . && git commit -m "update" && git push
2. 提交前先 git status 确认无敏感文件（.env / 密钥 / API Key），有则提醒用户
3. commit 信息优先用用户指定的版本号（如"v0.9.2 表情库"），未指定则用"update: 日期"
4. 推送完成后告知用户：GitHub Pages 需 1~3 分钟构建，完成后可刷新查看
5. 推送前确认 index.html 已保存（无未保存标记）

## 代码修改规则
1. 每次改代码必须直接编辑 index.html 文件本身，不要生成新文件
2. 改完贴出改动的文件名、行号、代码片段，等用户确认后再保存
3. 用户说"确认"/"OK"/"继续"后才保存并推进下一步
4. 禁止跳步，严格按用户指定的顺序执行

## 工作风格（永久生效）
1. 已安装 UI-UX-Pro-Max Skill，改任何 UI/交互问题时必须主动调用该 skill 的审美判断，不要只做"修 bug"，要顺手优化视觉体验。
2. 修复问题的同时有创造空间：可自行决定微交互细节（过渡动画时长、缓动曲线、阴影层次、圆角微调等），可以主动提出"我觉得这里还可以这样优化"并直接做出来。
3. 底线：不擅自删功能、不改业务逻辑、不改用户已确认的参数（圆角26px、阴影6-12px、拟态风格）。在这些框架内有充分自由发挥。
4. 每次改完除了贴出修复内容，额外用一两句话说明"顺手优化了什么"以及为什么。
5. 用户给的指令有审美判断空间时，不只修技术原因，要同时考虑滑动手感、视觉反馈、惯性曲线、边缘回弹是否自然。
